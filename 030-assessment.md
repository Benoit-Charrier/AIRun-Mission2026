
**Assessment Questions — Module 030: AI Factories and EPAM**

1. *(W1)* What changes when you stop thinking about "one AI Factory" and start thinking about a network of factories?
    One factory cannot cover all domains correctly. Specialization is the point — each factory has a domain, input, output, owner, and review logic. Thinking in a network means assembling the right factories for the opportunity and defining how they hand artifacts to each other.

2. *(W2)* In the supply-chain analogy, what moves between factories when tools or data cannot be shared directly?
    Human-reviewed artifacts — the safe handoff when direct integration is blocked by data, security, or compliance constraints.

3. *(W3)* Name one situation where you would look for an existing EPAM Factory and one situation where you would create a new customer-specific Factory.
    Reuse: user story creation using Confluence and Jira — domain-generic, tool-compatible with EPAM accelerators. Create: integration with a customer-specific system — the client's context is too specific to fit an existing asset without rebuilding it anyway.

4. *(W4)* Why do client-owned infrastructure and mixed EPAM/client teams make Factory setup an operating-model problem, not only a tooling problem?
    Because prompts, artifact formats, gates, and evidence must survive tool substitution. When the client's infrastructure replaces EPAM's preferred tools, the operating model — who owns what, which artifacts move where, which human approves what — must hold regardless.

5. *(W5)* Which role usually sees the earliest customer signal, and which role usually keeps the delivery loop coherent until successful delivery?
    Account Manager (Client Partner) sees the earliest customer signal. Delivery Manager keeps the loop coherent from signal through to successful delivery.
