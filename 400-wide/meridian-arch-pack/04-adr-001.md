# ADR-001: Adopt an Event-Driven Inventory Read Model (Kafka + Redis) over Synchronous SAP Reads

## Context

Meridian Phase 1 requires per-SKU inventory availability on every product page (web + mobile) and in the POS cart-bridge. SAP ECC is the inventory ground truth, but its RFC gateway cannot sustain real-time query load at e-commerce scale — the Black Friday 2024 EU outage was partially caused by synchronous ERP queries on the hot read path. At 8000 RPS peak (K 4.W.7 NFR #2), direct SAP reads would saturate the RFC gateway within minutes.

Trade-off scoring against K 4.W.2 options on four constraints:

| Option | PSD2 SCA latency | SAP batch reality | Junior team operability | Strangler-fig coexistence |
|--------|-----------------|-------------------|------------------------|--------------------------|
| A — Sync SAP reads | Neutral | **Fails** — RFC saturation at peak | **Best** — no new ops | **Neutral** |
| **B — Kafka + Redis cache** | **Best** — Redis reads in < 5ms | **Best** — decouples SAP | Acceptable — CDC adds ops | Neutral |
| C — Buy inventory SaaS | Neutral | Best — vendor owns it | **Fails** — procurement delay > 4 months | Neutral |

Option B wins on the two most critical constraints (SAP stability at peak, latency for PSD2 SCA checkout path). Option C fails on the 18-month delivery timeline.

## Decision

We will hydrate a Redis inventory read cache from SAP stock-change events published to Kafka via a CDC connector. The platform reads stock from Redis; SAP ECC is queried inline only on a cache miss, with a `cannot_confirm` degraded-availability response when SAP is unreachable or the cache miss timeout exceeds 1000ms.

## Alternatives Considered

1. **Option A — Synchronous RFC reads from SAP ECC on every stock query** — rejected because SAP ECC RFC gateway throughput (~100–200 concurrent RFC sessions) is insufficient for ~8000 RPS e-commerce peak without a dedicated SAP scale-out that is outside the $42M programme budget and would not be delivered within the 18-month window.

2. **Option C — Buy cross-channel inventory SaaS (e.g. OneStock, Fluent Commerce)** — rejected because procurement and integration of a new SaaS vendor adds 2–4 months of contract and onboarding time the Phase 1 stage gates cannot absorb; it also introduces a third critical external dependency (alongside Stripe and Auth0) whose outage would be outside Meridian's control at Black Friday.

## Consequences

- **Positive:** SAP ECC is off the synchronous hot path; a 2-hour SAP maintenance window no longer cascades to store POS or web checkout. Redis reads (< 5ms) contribute negligibly to the PSD2 SCA checkout latency budget.
- **Negative:** The Kafka CDC pipeline (Debezium connector, schema registry, consumer-group lag monitoring) adds operational complexity. The junior MRG team will need 4–6 weeks of Kafka operations onboarding and runbooks before Phase 1 launch. Inventory data in Redis is 15–30 min stale at worst on slow SAP batch segments — the confidence-label and disclosure design from Module 300 (AI-AC1, AI-AC6) is the user-facing mitigation for this lag.

## Agent-Readable Summary

All inventory availability reads use the Redis Inventory Read Cache hydrated from SAP stock-change events via Kafka. Do not introduce synchronous calls from any service (Gateway, Cart Service, Checkout Service, POS Client) directly to SAP ECC on the read path. The only permitted synchronous SAP call is a cache-miss inline fallback in the Gateway, and it MUST apply a 1000ms timeout that degrades to a `cannot_confirm` response rather than blocking the caller.
